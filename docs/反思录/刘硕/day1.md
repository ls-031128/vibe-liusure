\# Day 1 反思录



\## 1. 今天完成了什么



今天完成了教务器材预约页面的设计、实现和本地验证。



项目使用原生 HTML、CSS、JavaScript 实现，不使用后端和数据库。页面包含三种教务器材，用户可以选择日期和时间段进行预约。



预约记录使用浏览器 localStorage 保存。



\## 2. 今天最大的收获



今天最大的收获是认识到使用 AI 开发并不是简单地告诉 AI “帮我写一个项目”。



实际过程包括：



需求分析 → 设计文档 → Implementation Plan → 测试 → 实现 → 自动测试 → 浏览器人工验证 → Git 提交 → Gitee 推送。



其中，我第一次比较完整地经历了让 AI 按照计划逐步实现一个小项目的过程。



\## 3. 我对 AI 编程的理解



AI 可以快速生成代码，但代码是否满足需求仍然需要自己验证。



例如本次项目中，最重要的业务规则是：



同一器材 + 同一天 + 同一时间段不能重复预约。



不能因为 AI 告诉我“已经实现”就认为功能一定正确，而应该通过测试和实际操作验证。



\## 4. 今天遇到的问题



开始开发时，项目目录 `vibe-lab1` 不是 Git 仓库，因此无法直接进行 Git 提交。



后来明确了课程个人 Gitee 仓库是 `vibe-liusure`，将 `vibe-lab1` 放入个人仓库后，再统一进行 commit 和 push。



另外，Gitee 开启了 2FA，Git HTTPS 推送需要使用 Personal Access Token，而不是普通登录密码。



\## 5. 我发现自己的不足



目前我对 Git、项目结构和 JavaScript 工程实践还不熟悉。



这次很多操作是在 AI 的指导下完成的，因此我还不能说自己完全掌握了这些技术。



后续需要继续理解：



\- Git 的 commit、push、tag 和分支

\- JavaScript 的模块化

\- localStorage

\- 自动化测试

\- 如何阅读和检查 AI 生成的代码



\## 6. 今天对 Vibe Coding 的认识



我认为 Vibe Coding 并不意味着完全不需要技术基础。



AI 可以降低写代码的门槛，但开发者仍然需要能够：



1\. 明确需求

2\. 判断方案是否合理

3\. 检查 AI 生成的代码

4\. 设计测试

5\. 验证实际结果

6\. 使用 Git 管理和交付项目



因此，我接下来希望提高的不是单纯的代码输入速度，而是需求分析、代码理解、测试和项目交付能力。



\## 7. 明天需要改进的地方



明天继续开发时，我会尽量先理解 AI 给出的方案，再执行代码，而不是只关注最终结果。



同时记录自己的问题和解决过程，为后续项目积累经验。
