## 2. 技术栈与连接方式

| 层次 | 当前实现 |
| --- | --- |
| 页面与 API | Next.js App Router、React、TypeScript，Vercel 托管 |
| 数据访问 | Prisma 7.10.0、`@prisma/adapter-pg`、PostgreSQL 驱动 |
| 数据库 | Neon PostgreSQL，运行时通过服务端 `DATABASE_URL` 连接 |
| 图表 | Recharts，展示用户手动填写的风险标签与记录数量 |
| AI | 服务端 DeepSeek Chat Completions，不向前端暴露 Key |
| 访问统计 | Prisma Visitor 模型，首页客户端加载后异步记录并查询累计次数 |

数据库连接沿用已经验证的配置，不因为新增统计而更换密码。运行时 PostgreSQL 连接与 CLI 迁移直连配置分开，不能把本地 SQLite 归档地址用于 Vercel。

## 4. Visitor 模型与迁移说明

| Prisma 字段 | 数据库字段与类型 | 默认值 | 业务含义 |
| --- | --- | --- | --- |
| `id` | `id TEXT`，主键、非空 | 数据库无默认值 | 接口生成 UUID，标识一次页面访问事件 |
| `createdAt` | `created_at TIMESTAMP(3)`，非空 | CURRENT_TIMESTAMP | 记录写入时间 |
| `path` | `path TEXT`，非空 | `/` | 当前仅记录首页路径，不包含查询参数或片段 |

迁移按顺序应用：

1. `20261014000000_add_visitors`：创建表。如果已在迁移账本中应用，不要重复手动建表。
2. `20261014010000_add_visitor_path`：增加 path，默认 `/` 回填原有首页访问事件，保留原记录。

本轮仅创建迁移文件并校验 Schema，没有执行任何线上迁移。不要修改已应用的旧迁移，也不要重置数据库。

**迁移保护边界：**项目现有 `npm run db:migrate:deploy` 仅接受人工确认的 Neon test 分支，不能将它误当作 Production 迁移脚本。测试分支按已有保护流程执行；线上数据库需先确认实际分支、迁移账本和备份，再在负责人批准的生产维护流程中应用迁移。不要为了上线绕过当前保护或把测试连接替换为生产连接运行测试。

先完成数据库变更，再将当前代码发布到 Vercel。否则统计会按要求静默失败：页面仍显示，但不会记录访问，也不会显示累计次数。

## 5. 手机访问与真实数据验收

1. 教师手机通过移动网络或不同 Wi-Fi 打开上述 HTTPS 地址，确认无需项目开发者登录即可访问。
2. 确认首页、表单及图表没有明显溢出或遮挡。
3. 刷新宠物列表，确认看到已有宠物；如需演示录入，使用虚构教学宠物，不录入身份信息。
4. 选择有评估记录的宠物，核对历史记录与图表；没有记录时按表单录入一条教学观察摘要。
5. 刷新页面或换一个浏览器，确认仍能查询刚保存的记录，以验证数据库持久化而不是只保存在前端状态中。
6. 记录验收时间、手机/浏览器及脱敏截图，不把 Key、连接串或环境变量面板放入截图。

## 6. AI 功能验收

1. 选择已有演示宠物，在 AI 助手输入日常护理或观察问题。
2. 确认提交和加载状态正常，成功接口返回 HTTP 200 与非空 answer，页面展示护理建议和不确定性/兽医提醒。
3. 确认没有把用户手动风险标签当作疾病确诊，没有提供处方或药物剂量。
4. 切换宠物后，旧回复应清除，不混入前一只宠物的资料。
5. 正常失败响应应显示“AI服务暂时不可用，请稍后重试”；HTTP 400 只验证参数校验，HTTP 503 只验证友好错误，都不能代替成功问答。

真实 AI 调用可能计费，应以少量教学请求完成验收。本轮自动化测试使用 HTTP 替身，没有验证真实 Key 或模型响应。

## 7. 访问统计验证

首页渲染完成后发送 `POST /api/visitors`，固定保存 path `/`。服务端 try/catch 静默处理失败，不存 IP、User-Agent、Cookie、账号或健康问题。开发 Strict Mode 的重复 effect 共享一次 POST；刷新或重新挂载视为新的访问。

POST 完成后客户端通过 `GET /api/visitors` 查询 `{count:数字}`，在首页底部显示“累计首页访问次数”。读写都不阻塞首页渲染；查询失败返回 `{count:null}`，页面隐藏统计区域，不显示错误或把失败伪装成 0。

| 验证方法 | 通过标准 |
| --- | --- |
| 手机刷新首页 | 新事件落库后累计次数增加，原有功能继续正常 |
| 浏览器 Network | POST 返回 204，随后 GET 返回 200 和真实 count；没有 Key 或健康信息请求体 |
| 数据库只读检查 | visitors 有新增 id、created_at、path `/` |
| 失败体验 | 在浏览器阻止统计接口请求后，首页及原有功能正常，统计错误不弹出 |

POST 成功和数据库失败都返回 204，不能只凭状态码判定落库。由负责人在已确认的数据库中运行只读 SQL：

```sql
SELECT COUNT(*) AS homepage_views FROM visitors WHERE path = '/';
SELECT id, created_at, path FROM visitors ORDER BY created_at DESC LIMIT 5;
```

该统计是尽力而为的页面访问量，不是唯一访客人数；禁用 JavaScript、请求被拦截或数据库故障都可能漏记。
