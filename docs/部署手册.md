### Vercel 配置与后续更新

1. 当前项目 Root Directory 对应 `pet-health-platform`，使用 Next.js 服务端部署，不做静态导出。
2. Build Command 使用 `npm run build`，包含 Prisma Client 生成；Vercel 负责启动服务端应用，不执行 Docker 启动命令。
3. 在 Vercel 项目环境变量页面分别管理 Production 与 Preview 配置，不上传本地 `.env`：
   - `DATABASE_URL`：Neon PostgreSQL 运行时地址，不使用 SQLite 归档地址。
   - `DIRECT_URL`：当前 Prisma CLI 配置需要的 PostgreSQL 地址；迁移连接应为核对目标后的直连地址。
   - `AI_API_KEY`：仅服务端使用的 DeepSeek Key。
   - `AI_API_BASE_URL`：`https://api.deepseek.com`。
   - `AI_MODEL`：沿用线上实际可用配置，不因文档同步更换模型。
4. 环境变量或源码更新后，重新部署对应版本，再核验首页、ping、宠物及评估读取、统计和 AI。不要以构建通过或 ping 正常代替数据库与 AI 验收。
5. 构建不会自动执行 migration。未来新增迁移前先备份、确认目标和批准迁移流程；当前 test 专用保护脚本不得用于 production，也不能绕过保护。

本轮仅更新文档和读取公网接口，没有运行迁移、重新部署或检查私密环境变量。当前状态取代早期“未部署”“统计接口 404”的记录；相关历史步骤可参考 [线上部署验收](./线上部署验收.md)，但不可把其中旧状态当作 Day 9 现状。

## 1. 环境要求与项目适配

| 项目 | 要求 |
| --- | --- |
| 服务器 | Ubuntu 22.04/24.04 LTS；实际版本、架构和资源需登录后确认 |
| 容器工具 | Docker Engine、Docker Compose v2 和 BuildKit；可访问镜像仓库和 npm registry |
| Node.js | 镜像使用 `node:22-bookworm-slim`；Prisma 7 在 22 系列要求至少 22.12；宿主机无需安装 Node |
| 数据库 | 已批准的 PostgreSQL，包含当前迁移定义的表；不能使用 `file:` SQLite 地址 |
| 网络 | 允许应用访问 PostgreSQL 和 DeepSeek；公网端口需同时获云安全组及防火墙放行 |
| 配置 | 可用的 SSH 登录；真实变量仅保存在服务器，不提交 Git |

项目有 App Router 服务端 API，适合常驻 Node 容器，不能导出为纯静态站点。`next.config.ts` 开启 `output: 'standalone'`；Dockerfile 使用锁文件安装依赖，生成 Prisma Client，构建后只复制 standalone、静态资源和 public 目录。最终以非 root 用户启动 `node server.js`。依据见 [Next.js standalone 文档](https://nextjs.org/docs/app/api-reference/config/next-config-js/output) 和 [Prisma 7 系统要求](https://www.prisma.io/docs/orm/v7/reference/system-requirements)。

Docker 未安装时按 [官方 Ubuntu 安装指南](https://docs.docker.com/engine/install/ubuntu/)安装 Engine、Buildx 和 Compose 插件。登录后先检查：

```bash
cat /etc/os-release
docker version
docker compose version
```

后续命令假定当前账号有 Docker 权限；否则按服务器管理方式使用 `sudo docker`。

## 2. 安全上传当前源码

必须包含当前新增的 Docker、访问统计和迁移文件，不能只上传尚未包含它们的旧 commit。排除 `.env`、node_modules、构建输出和 SQLite 归档。

Windows PowerShell 示例，先替换服务器信息：

```powershell
$repoPath = 'C:\Users\刘硕\Desktop\vibe-liusure'
$serverHost = '<服务器公网IP>'
$serverUser = '<SSH用户名>'
$serverPort = 22
$archivePath = Join-Path $env:TEMP 'pet-health-platform-day4.tar.gz'
tar -czf $archivePath --exclude='pet-health-platform/.env*' --exclude='pet-health-platform/node_modules' --exclude='pet-health-platform/.next' --exclude='pet-health-platform/generated' --exclude='pet-health-platform/prisma/*.db*' --exclude='pet-health-platform/*.tsbuildinfo' -C $repoPath pet-health-platform
scp -P $serverPort $archivePath "${serverUser}@${serverHost}:pet-health-platform-day4.tar.gz"
# 打包规则同时排除了环境示例，因此只单独发送这个不含密钥的模板。
scp -P $serverPort "$repoPath\pet-health-platform\.env.production.example" "${serverUser}@${serverHost}:env.production.example"
```

非默认 SSH 密钥可在命令添加 `-i <本地密钥路径>`，不要上传私钥。首次部署在服务器解压到专用目录；如果已有部署，先检查和备份，不覆盖现有环境文件：

```bash
mkdir -p ~/pet-health-platform-day4
tar -xzf ~/pet-health-platform-day4.tar.gz -C ~/pet-health-platform-day4 --strip-components=1
cd ~/pet-health-platform-day4
cp ~/env.production.example .env.production.example
cp -n .env.production.example .env.production
chmod 600 .env.production
nano .env.production
```

## 3. 环境变量

| 变量 | 用途与配置 |
| --- | --- |
| `DATABASE_URL` | 已批准且已迁移的 PostgreSQL 运行时连接；Neon 可使用 pooled URL，保留平台要求的 SSL 参数，不使用本地 SQLite 地址 |
| `AI_API_KEY` | 仅在服务器填写有效的 DeepSeek Key |
| `AI_API_BASE_URL` | 默认 `https://api.deepseek.com` |
| `AI_MODEL` | 与实际可用模型和价格对应，当前默认 `deepseek-flash` |
| `APP_PORT` | 宿主机 HTTP 端口，默认 3000 |
| `APP_BIND_ADDRESS` | 默认 `0.0.0.0`；同机反向代理可改为 `127.0.0.1` |

Compose 使用 `env_file` 在运行时注入 `.env.production`，见 [Docker 环境变量说明](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/)。所有命令显式指定 `--env-file .env.production`，避免使用本地归档配置。

真实变量不作为 build 参数。构建仅用本机占位 PostgreSQL URL 满足现有 Prisma 初始化校验，不执行迁移；`.dockerignore` 排除所有 `.env*` 文件，Git 只允许提交示例。不要公开粘贴完整 `docker compose config`、`docker inspect` 或环境文件；配置检查使用 `config -q`。

## 4. 数据库与访问统计迁移

迁移 `20261014000000_add_visitors` 创建访问表，`20261014010000_add_visitor_path` 补充路径，最终字段为 `id`、`created_at`、`path`。当前 Vercel 统计查询已正常；本轮没有独立读取迁移账本或执行迁移。对于新的 Docker 环境仍须核对其实际数据库结构。应用启动不会自动迁移或导入 SQLite 数据，最终运行镜像也不包含迁移 CLI。

现有受保护脚本只接受人工核验的 Neon **test** 分支。课程验收若使用该分支，可以构建维护镜像并运行保护流程。在服务器用编辑器创建 `.env.migration`，填写下列变量，权限设为 600：

| 迁移变量 | 用途 |
| --- | --- |
| `DIRECT_URL` | test 分支的非池化直连地址 |
| `TEST_DATABASE_URL` | 同一 test 分支的池化地址 |
| `NEON_TEST_BRANCH_ID` | 控制台人工核对的 test 分支 ID |
| `NEON_TEST_ENDPOINT_ID` | 与两条 URL 一致且人工核对的 endpoint ID |

```bash
nano .env.migration
chmod 600 .env.migration
docker build --target builder -t pet-health-platform:migration .
docker run --rm -it --env-file .env.migration pet-health-platform:migration npm run db:migrate:deploy
```

再次在 Neon 控制台核对目标，按提示输入实际 `test/<branch ID>`。脚本使用 `prisma7.config.ts` 中的 PostgreSQL 专用迁移目录。若拒绝或失败立即停止，不运行 reset/db push，也不使用普通 Prisma 命令绕过保护。

运行时 `DATABASE_URL` 必须指向同一已确认数据库。若要使用 production 分支或其他 PostgreSQL 服务，应另行确认生产迁移流程，不能强行复用或绕过当前 test 保护。原 SQLite 数据和迁移历史继续保留本地，不上传、不覆盖；新迁移不更改已有宠物与评估表。

## 5. Docker 构建与启动命令

在项目目录执行：

```bash
docker compose --env-file .env.production config -q
docker compose --env-file .env.production build
docker compose --env-file .env.production up -d
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=100 app
```

等待 app 进入 healthy。健康检查只验证 `/api/ping`，不证明数据库或真实 AI 正常。该 Docker 路线的外部访问格式为 `http://<服务器公网IP>:3000/`，实际端口以 `APP_PORT` 为准，尚未实际部署；当前已运行的 Vercel 地址见线上验收文档。

域名备案期间可按云平台规则先尝试公网 IP。端口不通时检查容器监听、映射、安全组和防火墙，开放端口时保留 SSH 访问规则。备案完成后可配置反向代理和 HTTPS，再记录实际域名与证书结果。

## 6. 首次上线验收

将 `BASE_URL` 替换为实际公网地址，并至少用教师手机或另一台设备访问首页：

```bash
BASE_URL='https://vibe-liusure.vercel.app'
# 验证 Docker 备选实例时再替换为其实际地址。
curl -fsS "$BASE_URL/"
curl -fsS "$BASE_URL/api/ping"
# 此请求只验证 AI 参数校验，应返回 400。
curl -sS -i -X POST "$BASE_URL/api/ai/pet-advice" -H 'Content-Type: application/json' --data '{"question":"测试"}'
```

| 验收项 | 通过标准 |
| --- | --- |
| 首页 `/` | 外部浏览器显示页面，静态资源正常 |
| `/api/ping` | HTTP 200，返回 `{"ok":true}` |
| AI 参数校验 | 缺少 petId 返回 400；不能据此认定真实 AI 成功 |
| 真实 AI | 页面选择已有演示宠物后提问，返回 HTTP 200 和非空 answer，宠物上下文正确；503 友好错误不算成功 |
| 原有闭环 | 宠物、评估历史和图表展示实际记录，刷新后仍可查询 |
| 访问统计 | 浏览器首页加载后发送 POST /api/visitors，数据库出现新记录；刷新可再记录 |
| 静默失败 | 浏览器阻止统计请求后，首页仍正常显示，没有额外统计错误提示 |
| 重启与窄屏 | 容器重启后数据库记录仍在，手机/窄屏页面可用 |

统计接口成功与失败均返回 204，必须在已确认数据库中通过只读查询验证落库，例如在 Neon SQL 编辑器执行：

```sql
SELECT COUNT(*) AS page_views FROM visitors;
SELECT id, created_at, path FROM visitors ORDER BY created_at DESC LIMIT 5;
```

它统计近似页面访问量，不是去重人数；不记录 IP、账号、Cookie 或健康问题。客户端加载后才异步发送，关闭 JavaScript、网络阻断或数据库故障可能漏记；首页服务端渲染不等待统计。

## 7. 更新与恢复

更新源码仍排除环境文件及构建产物，保留服务器配置。有新迁移时先按批准流程备份和迁移，再执行：

```bash
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
```

更新前保存上一版镜像/源码和 PostgreSQL 备份；回滚镜像不等于恢复数据库。不要通过清空数据库、重置迁移或覆盖 SQLite 归档来修复部署错误。重启策略会重启退出的进程，健康状态本身不等于完整监控。

当前 MVP 没有登录或调用配额，公网课程演示应控制访问范围、使用虚构信息并关注 AI 账单。AI 建议不能替代兽医诊断。
