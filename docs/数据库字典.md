# 数据库字典

更新日期：2026-10-13。

本文以当前 [Prisma Schema](../pet-health-platform/prisma/schema.prisma)、[PostgreSQL 结构 SQL](../pet-health-platform/db/schema.sql) 和 [PostgreSQL 初始迁移](../pet-health-platform/prisma/migrations-postgresql/20261010120000_init_postgresql/migration.sql) 为依据。三者声明的业务表、字段、非空约束、主键、外键和默认值一致。

当前数据库方案为 PostgreSQL，业务表位于 `public` schema。本次仅阅读仓库文件，未连接数据库；本文描述代码所定义的结构，不作为线上数据库无结构漂移的证明。原 SQLite 文件及迁移历史属于归档，不作为当前结构依据。

## 1. 数据表总览

| 数据表 | Prisma 模型 | 业务用途 | 主键 |
| --- | --- | --- | --- |
| `public.pets` | `Pet` | 保存宠物最小基本资料 | `id` |
| `public.health_assessments` | `HealthAssessment` | 保存用户手动填写的初步风险提示与观察摘要 | `id` |

当前项目 Schema 共定义 2 张业务表。Prisma 的迁移管理表（如 `_prisma_migrations`）属于框架元数据，不在本项目业务模型中；本文不展开其字段，也未核验线上迁移账本。

## 2. pets：宠物基本资料

| 数据库字段 | Prisma 字段 | PostgreSQL 类型 | Prisma 类型 | 允许 NULL | 数据库默认值 | 业务含义 |
| --- | --- | --- | --- | --- | --- | --- |
| `id` | `id` | `TEXT` | `String` | 否 | 无 | 宠物唯一标识，主键；当前创建 API 使用 `randomUUID()` 生成后写入，不是数据库自动生成 |
| `name` | `name` | `TEXT` | `String` | 否 | 无 | 宠物名称 |
| `species` | `species` | `TEXT` | `String` | 否 | 无 | 宠物物种，如猫、狗；不代表具体品种 |
| `age` | `age` | `INTEGER` | `Int` | 否 | 无 | 宠物年龄，页面单位为岁；当前 API 接受非负整数 |
| `created_at` | `createdAt` | `TIMESTAMP(3)` | `DateTime` | 否 | `CURRENT_TIMESTAMP` | 创建时间；Prisma 对应 `@default(now())`，未提供值时由数据库填写 |

| 约束名称 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| `pets_pkey` | 主键 | `id` | 保证每只宠物的标识唯一且非空 |

当前没有 `breed` 品种字段、主人身份字段或登录用户关联字段。

## 3. health_assessments：健康评估记录

| 数据库字段 | Prisma 字段 | PostgreSQL 类型 | Prisma 类型 | 允许 NULL | 数据库默认值 | 业务含义 |
| --- | --- | --- | --- | --- | --- | --- |
| `id` | `id` | `TEXT` | `String` | 否 | 无 | 评估记录唯一标识，主键；当前创建 API 使用 `randomUUID()` 生成后写入 |
| `pet_id` | `petId` | `TEXT` | `String` | 否 | 无 | 所属宠物 ID，外键关联 `pets.id` |
| `risk_level` | `riskLevel` | `TEXT` | `String` | 否 | 无 | 用户手动填写的初步风险提示标签；不是医学风险评分、AI 自动评估或疾病诊断结论 |
| `summary` | `summary` | `TEXT` | `String` | 否 | 无 | 用户手动填写的观察摘要 |
| `created_at` | `createdAt` | `TIMESTAMP(3)` | `DateTime` | 否 | `CURRENT_TIMESTAMP` | 记录创建时间；Prisma 对应 `@default(now())` |

| 约束或索引名称 | 类型 | 字段/关联 | 说明 |
| --- | --- | --- | --- |
| `health_assessments_pkey` | 主键 | `id` | 保证记录标识唯一且非空 |
| `health_assessments_pet_id_fkey` | 外键 | `pet_id` → `pets.id` | 关联的宠物必须存在；`ON DELETE CASCADE`、`ON UPDATE CASCADE` |
| `health_assessments_pet_id_idx` | 普通索引 | `pet_id` | 支持按宠物查询记录；不是唯一索引，同一宠物可以有多条记录 |

## 4. 关系与字段映射

| 项目 | 说明 |
| --- | --- |
| 表关系 | `pets` 与 `health_assessments` 为一对多；一只宠物可以没有评估记录，也可以有多条记录 |
| `Pet.assessments` | Prisma 关系集合，不是 `pets` 中的实体列 |
| `HealthAssessment.pet` | Prisma 关系对象，不是数据库实体列；实际关联通过 `pet_id` 保存 |
| 表名映射 | `@@map("pets")`、`@@map("health_assessments")` 指定实际表名 |
| 字段映射 | `createdAt` → `created_at`、`petId` → `pet_id`、`riskLevel` → `risk_level` |
| 删除关联 | 按当前外键定义，删除宠物会级联删除其评估记录；该说明描述约束，不表示项目已提供删除 API |

## 5. 数据类型与业务边界说明

| 项目 | 当前实际定义 |
| --- | --- |
| 非空与空字符串 | 所有实体字段均为 `NOT NULL`；非空约束本身不禁止空字符串。名称、物种、风险标签和摘要的非空白校验位于现有 API |
| 年龄约束 | 数据库字段为 `INTEGER`，SQL 未定义非负 `CHECK`；非负整数校验由宠物创建 API 执行 |
| 风险标签 | 当前是自由文本，没有枚举、医学阈值或数据库诊断规则 |
| ID 类型 | 实际列为 `TEXT`，不是 PostgreSQL `UUID` 类型；Schema 未设置 UUID 默认值 |
| 创建时间 | `TIMESTAMP(3)` 为毫秒精度、无时区的 PostgreSQL 时间列，不是 `TIMESTAMPTZ`。API 将 Prisma 时间值序列化为 ISO 字符串；应结合现有应用约定解释时间，不把列类型当成时区配置 |
| 未存储的数据 | 当前没有保存 AI 问题、AI 回复、用户身份信息或疾病诊断数据的表和字段；`summary` 是手动观察摘要 |

后续 Schema 或迁移发生变化时，应同步更新本文，优先采用 Prisma Schema 与对应数据库迁移定义。
