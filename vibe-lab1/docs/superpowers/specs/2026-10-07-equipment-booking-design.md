# 教务器材预约页面设计

## 目标

创建一个可以直接在浏览器中运行的大学课程作业演示页面，用于展示三种教务器材并完成本地预约。页面不依赖后端或数据库，预约记录保存在当前浏览器的 `localStorage` 中。

## 范围与约束

- 页面展示三张器材卡片，每张包含名称、简介和“预约”按钮。
- 预约流程要求选择日期和时间段后提交。
- 同一器材、同一天、同一时间段只能预约一次。
- 冲突预约必须被拒绝，并给出清晰的中文提示。
- 视觉风格简洁、干净、适合课程作业演示，并兼容窄屏。
- 不引入后端、数据库或构建工具；打开 `index.html` 即可运行。

## 文件设计

- `index.html`：页面骨架、器材卡片容器、预约弹窗/表单、提示区域。
- `styles.css`：颜色、间距、卡片、弹窗、状态提示和响应式布局。
- `booking.js`：不依赖 DOM 的预约记录解析、冲突判断和创建预约逻辑；同时兼容浏览器全局对象和 Node 测试环境。
- `app.js`：器材数据、DOM 渲染、表单交互和 `localStorage` 适配。
- `tests/booking.test.js`：使用 Node 内置测试运行器覆盖核心预约规则。
- `package.json`：提供 `npm test` 脚本，不添加运行时依赖。

## 数据与交互流程

预约记录统一存储在 `localStorage` 的 `equipmentBookings` 键中，记录至少包含 `equipmentId`、`date` 和 `timeSlot`。用户点击器材卡片上的按钮后打开预约面板；提交时将三项字段组合成唯一预约键，并检查现有记录。不存在冲突时写入本地数据并显示成功信息；存在冲突时不写入，并显示拒绝信息。

核心逻辑会放在 `booking.js` 的可独立测试纯函数中：读取/规范化预约记录、判断时段是否已被占用、创建预约并返回成功或冲突结果。浏览器层只负责把表单输入交给这些逻辑、读写本地存储并更新界面。

## 验证方案

- 自动测试覆盖首次预约成功、相同器材/日期/时段冲突、不同器材可预约、不同日期或时段可预约，以及记录持久化数据的解析。
- 页面手动验证覆盖：三张卡片显示、打开和关闭预约面板、成功提交、冲突提示、刷新页面后冲突仍然存在、窄屏布局。

## 明确不做

- 不做用户登录、管理员审核、取消预约、跨设备同步、后端接口或真实数据库。
